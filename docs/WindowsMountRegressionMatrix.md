# Windows 挂载回归矩阵

本矩阵覆盖 Cloud Files 与 WinFsp 的 Explorer 真实操作；执行前请记录 bridge 日志，并在每个场景后刷新客户端、Explorer 与对象存储网页端。

| 场景 | 前置条件 | 操作 | 通过标准 |
| --- | --- | --- | --- |
| 严格只读 | 已安装 WinFsp；桶可读 | 在挂载弹窗选择“只读挂载”，在 Explorer 新建、改写、删除、重命名 | 挂载引擎自动为 WinFsp；每个写操作立即被 Windows 拒绝，云端和本地都没有伪成功副本 |
| 卸载保留缓存 | Cloud Files 默认路径挂载并水合文件 | 卸载，保持“同时删除本地缓存”关闭 | 挂载解除；默认同步目录和已下载本地文件保留，云端不变 |
| 卸载清理缓存 | Cloud Files 默认路径挂载并水合文件 | 关闭所有打开文件，卸载并打开“同时删除本地缓存” | 挂载解除，默认同步目录被删除，云端对象不变 |
| 占用文件卸载 | 在挂载目录打开 Office/文本文件 | 发起卸载 | 确认框提示先关闭文件；若仍选择删除缓存且文件锁阻止清理，挂载仍解除并报告需关闭占用后再次清理 |
| 恢复后再操作 | 已挂载桶；回收站有文件和目录 | 在客户端恢复，再从挂载目录删除和重命名 | 恢复项立即回到 Explorer；删除、重命名均成功且远端状态一致 |
| 跨桶移动 | 同一账号下 A/B 两个桶均已挂载；准备文件、空目录、非空目录 | 依次从 A 拖动/剪切到 B；中断一次目标写入后重试 | 成功时 B 完整出现且 A 不残留源 key/目录标记；失败时 A 保留原数据，日志能关联源、目标和失败阶段 |

跨桶移动是两个独立挂载 session 的组合操作，不应以“目标已出现”作为成功判断；必须同时检查源对象清理和目录标记。
